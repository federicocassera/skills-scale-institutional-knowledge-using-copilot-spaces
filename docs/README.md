# OctoAcme Project Management Docs

## Overview

OctoAcme follows a structured, iterative project management approach focused on delivering customer value through clear ownership, data-informed decisions, and continuous improvement. This documentation serves as the authoritative source for how we plan, execute, and deliver projects across the organization.

## Core Principles

- **Customer-first**: Prioritize customer value and usability
- **Iterative delivery**: Deliver small, testable increments
- **Clear ownership**: Each project has named PM and Product Lead roles
- **Data-informed decisions**: Measure impact and iterate based on evidence
- **Psychological safety**: Encourage feedback and learning

## Project Lifecycle

OctoAcme projects follow a consistent five-phase lifecycle:

1. **Initiation** → Define problem, validate business need, align stakeholders, and set high-level timeline
2. **Planning** → Scope work, estimate effort, define acceptance criteria, identify dependencies
3. **Execution** → Build, test, review, iterate, and track daily progress
4. **Release** → Deploy, verify, and announce to stakeholders
5. **Close & Retrospective** → Capture learnings and drive continuous improvement

### By Lifecycle Phase

#### Initiation
**[Project Initiation Guide](octoacme-project-initiation.md)**  
Validate business need, confirm measurable outcomes, identify stakeholders, and make the go/no-go decision to move into planning.

**Key activities:**
- Define problem statement and SMART goals
- Create Project One-pager
- Align stakeholders
- Identify risks and resource needs

#### Planning
**[Project Planning](octoacme-project-planning.md)**  
Turn an approved initiative into an actionable plan. Break work into shippable increments, estimate scope, identify dependencies, and create a release timeline.

**Key activities:**
- Conduct project kickoff
- Prioritize backlog with acceptance criteria
- Define Definition of Done
- Create release plan and milestones

#### Execution & Tracking
**[Execution & Tracking](octoacme-execution-and-tracking.md)**  
Manage day-to-day progress, maintain team rhythm through standups and syncs, ensure quality, and escalate blockers.

**Key activities:**
- Daily standups (15 min focus on progress, blockers, dependencies)
- Weekly delivery syncs
- Pull Request reviews and merging
- Quality assurance and testing
- Risk monitoring and escalation

#### Release
**[Release & Deployment Guide](octoacme-release-and-deployment.md)**  
Standardize how OctoAcme releases features to production. Reduce risk through pre-release checks, automated deployment, and rollback planning.

**Key activities:**
- Verify all acceptance criteria met
- Prepare release notes
- Deploy to staging and production
- Run smoke tests and post-deploy verification
- Announce release to stakeholders

#### Retrospective
**[Retrospective & Continuous Improvement](octoacme-retrospective-and-continuous-improvement.md)**  
Capture learnings and convert them into actionable improvements. Run after each sprint, release, or important milestone.

**Key activities:**
- Conduct retrospective (45–75 minutes)
- Identify what went well and what could improve
- Create action items with owners and due dates
- Track and measure impact of improvements

## Quick Reference

### Key Artifacts to Maintain
- Project Charter / One-pager (defined during Initiation)
- Sprint/Iteration Backlog with acceptance criteria (Planning & Execution)
- Definition of Done (Planning)
- Risk Register (Planning & ongoing)
- Release Plan and milestone map (Planning & Release)
- Retrospective notes and action items (Retrospective)

### Communication Cadence
- **Daily**: Team standups (15 min) — focus on progress, blockers, dependencies
- **Weekly**: PM + PdM sync, Delivery team standups
- **Monthly**: Stakeholder updates
- **Ad-hoc**: Escalations and incident communications

### Decision Gates

**Initiation → Planning**  
Move to planning when:
- Success metrics are clear and measurable
- Stakeholders agree on priority
- Team availability is confirmed

**Planning → Execution**  
Start execution when:
- Backlog is prioritized and estimated
- Definition of Done is documented and agreed
- Release timeline and milestones are set

### Core Roles

| Role | Responsibilities | Goals |
|------|------------------|-------|
| **Project Manager** | Coordinate delivery, manage schedules, risks, communications | Deliver on time, minimize escalations, maintain transparency |
| **Product Manager** | Define outcomes, prioritize backlog, measure success | Maximize customer value, make data-driven decisions |
| **Developer** | Implement features, write tests, participate in reviews | Deliver reliable code, reduce cycle time, maintain quality |
